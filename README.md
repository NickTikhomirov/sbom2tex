
# sbom2tex: CycloneDX SBoM to LaTeX (to PDF)

## Фичи

Главная фича: **трансляция CycloneDX SBoM в LaTeX (и, как следствие, в PDF);**
+ Поддержка ФСТЭКоSBoM-ов (по ныне публичной Методике ВУ и НДВ);
+ Полное представление о DependencyTrack-проекте за счёт слияния SBoM-ов `inventory`, `vdr` и исходного SBoM (обогащённого ФСТЭКосвойствами);
+ Настройка титульника через флаги

### Остальные фичи

+ Возможность разбить отчёт на несколько частей (флаг `--split`, влияет только на CVE)`;
+ Возможность отбросить компоненты с типами `file`, `cryptographic-asset`, `operating-system`, `container` -- флаги `--drop-buzz` и `--drop-obom`;
+ Гибкое управление директивными зависимостями в отчёте:
  + Изменение глубины понятия директивности (вместо L1 можно поставить любую глубину);
  + Добавление рёбер в обход компонентов с типом `operating-system` -- для расширения списка директивных зависимостей списком пакетов ОС;
+ Упрощение ревью результатов композиционного анализа:
  + Корреляция ПА с незакрытыми CVE -- см. флаги `-S` (`--review-attack-surface`) и `-SS`;
  + Цветовая подсветка незаполненных важных мест -- см. флаг `--shame`;
+ Есть Dockerfile для сборки, инкапсулирующий всю головную боль с LaTeX;

## Рекомендации по использованию

### И как это использовать??

Генератор принимает SBoM-файлы. Рекомендуется брать два файла -- `inventory` и `vdr` из Dependency Track.
На SBoM-файлы накладываются следующие ограничения:
+ Генератор не распознает проблемы с коллизиями `bom-ref`;
+ Генератор берёт только компоненты из поля `.components` SBoM-а -- если у вас SBoM закодирован списками смежности в ООП-стиле (используется поле `.components` в теле других компонентов), то оно будет проигноировано;

Выходом генератора является файл (или файлы) в формате XeLaTeX, который(ые) далее можно скомпилровать в PDF.
Файлы независимы с точки зрения XeLaTeX и могут быть скомпилированы в любом порядке друг относительно друга.


#### Пошаговый пример сборки без контейнера для отчёта с DT

1. Берём наш крутой обогащённый SBoM-файл с `GOST:attack_surface`, `GOST:security_function` и пр. -- назовём этот файл `A.json`
2. Загружаем `A.json` в Dependency Track, находим CVE, размечаем, оставляя комментарии (В ПРАВИЛЬНОМ ПОЛЕ!!)
3. Выгружаем файлы - - назовём их `inventory.json` и `vdr.json`
4. Вызываем генератор отчётов командой `python3 ./main.py -i vdr.json -i inventory.json -i A.json -o ./report/ --name "Проект A"`
5. Собираем выгруженный отчёт с помощью XeLaTeX.

#### Пошаговый пример сборки в контейнере

1. Аналогично предыдущему гайду
2. Аналогично предыдущему гайду
3. Аналогично предыдущему гайду
4. Сохраняем файлы в некоторую директорию, -- например, `./test/`:
   + `./test/inventory.json`
   + `./test/vdr.json`
   + `./test/A.json`
5. Собираем контейнер через `sudo docker build -t <тег> .` (извините, придётся потерпеть загрузку двухгигового контейнера texlive)
6. Запускаем контейнер командой:
```shell
sudo docker run -v ./test/:/test --rm -it <id контейнера> --name=ИМЯ_ПРОЕКТА -i /test
```

В результате сборки получается отчёт в той же директории, которую мы подали (в формате PDF).

### Что нужно для работы?

Для самого генератора не нужно ничего (кроме Python 3), но для LaTeX нужны кое-какие пакеты, перечисленные далее.
