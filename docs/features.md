# Возможности sbom2tex


## Кастомизация текста в отчёте

Базовая настройка титульного листа реализуется через флаги. Например:
```shell
python.exe .\main.py -i ..\vdr.json -o ../test --name="Отчёт о результатах композиционного анализа проекта ПАК <<Медуза-Литерал>> (исполнение Капит
ошка-4 с аппаратным ускорителем)" -t d -t "Часть 2" -t "Лаборатория N 15408" -t "Эксперт Иванов И.И." -t "amogus"
```

Для титульного листа доступны флаги:
+ ``--name`` -- имя документа
+ ``-t`` -- добавление подзаголовка, для этого флага арезервированы значения:
  + ``-t d`` -- дата генерации отчёта (текущее время)
  + ``-t t`` -- timestamp из первого переданного SBoM
  + ``-t s`` -- небольшая полосочка справа
  + ``-t r`` -- для одной строки (следующего флага `-t`) ставится выравнивание по правому краю
  + ``-t k`` -- тип отчёта (компоненты, уязвимости)
  + ``-t N`` -- часть отчёта (для многотомных отчётов)

Для титульников с большим количеством текста рекомендуется выбрать размер вручную с помощью флага `--subtitle-size` (принимает число без размерности, интерпретирует как `pt` из LaTeX);

Помимо перечисленных флагов также нужно знать о флаге `--intro-text`, с помощью которого можно добавить текст в первый (обзорный) раздел.

## Отображение только интересных компонентов

Генератор отбрасывает большую часть компонентов, поскольку нет смысла печатать 900 страниц с кучей библиотек за десятое колено транзитивности.
Для отключения этого механизма доступны флаги:
+ `-D` -- считать все директивные зависимости интересными;
+ `-A` -- считать вообще все зависимости интересными (включает в себя функционал `-D`);

### Критерии интересности компонентов

Остаются только компоненты, у которых есть хотя бы одно из свойств:
+ Имеется поле `GOST:provided_by` (этот параметр можно отключить через флаг `--provided-by-is-not-interesting`)
+ Поле `GOST:security_function` имеет любое значение кроме `no`
+ Поле `GOST:attack_surface` имеет любое значение кроме `no`
+ Имеется хотя бы одна CVE
+ Тип компонента отличается от стандартного набора `application`, `library` или `framework`
+ У компонента отсутствует правильный сурс (должно быть хотя бы одно из полей -- `GOST:provided_by` или `externalReferences` со значением `vcs` или `source-distribution`)


## Поддерживаемые поля, свойства и особенности SBoM

Для метаданных поддерживаются:
+ Корневой компонент;
+ Инструмент формирования SBoM;

Для компонентов поддерживаются:
+ Основные поля: `name`, `version`, `type`
+ Поле `purl`
+ Ссылки (`externalReferences`) типов `vcs` и `source-distribution`;
+ Свойство `GOST:attack_surface` (отключается флагом `--no-gost`);
+ Свойство `GOST:security_function` (отключается флагом `--no-gost`);
+ Свойство `GOST:source_langs`;
+ Свойство `GOST:provided_by`;

Для уязвимостей поддерживаются:
+ Поле `cwes`
+ Поле `recommendation` (fallback на `workaround` при отсутствии);
+ Ревью из поля `analysis` -- в частности, подпункты `detail` и `state`;


## Неподдерживаемые особенности SBoM

+ Не поддерживаются SBoM-файлы с рекурсивной структурой, т.е. с полем `components` в теле компонента -- все вложенные компоненты игнорируются;
  + Впрочем, Dependency Track раскладывает их в одноуровневый SBoM, так что не критично;
